# 灵感助手（MI · Music Inspirationist）

本机（Apple 芯片 Mac）上的 **纯离线** AI 音乐草稿工具 —— 也是 **Ableton Live 与
ACE Studio 之间的那座桥**。

填参数、点生成、听草稿；音频和谱子能送进 ACE Studio，ACE 里唱好的能拿回 Ableton Live，
Live 里选中的也能送进 ACE。**全程不出网** —— 没有一个字节发到云端。

上层模型是开源的 **YuE2**（本机 MLX 版）。我们只做三件事：装好它、给它一个壳、给它一个界面。
ACE-Step 1.5 那条是备选（2026-10-16 从界面拆下来了，代码与说明都留着，见第五章）。

> **想做 Windows 版？** 哪块能直接搬、哪块必须重写、机器要什么配置 ——
> 见 **[WINDOWS.md](WINDOWS.md)**。先说结论：界面和出声要重写，
> 「音频转谱」几乎白送，**真正卡人的是出歌那一步**（官方要 NVIDIA + 24 GB 显存）。

> ## 它是什么、不是什么（用户 2026-10-20 定）
>
> 它是 **inspirationist —— 灵感助手**：**一个会交作业的学徒，不是一台成品机。**
>
> - **它做的事**：你给它谱子（MusicXML），它**照着唱出来**；你改谱、它重唱。
>   让作曲家**马上听见**结构、词位、音高、节奏对不对。
> - **它不做的事**：不出成品。音质、咬字、稳定性都不如收费的云端产品。
>   **成品仍然进 ACE Studio 或别的云端。**
> - **它卖的是什么**：**「改一笔就能马上听一遍」**——免费、本地、谱子一个字节不上传。
>   不是「出一首能发的歌」。
>
> 一句话：**它替你交草稿，替不了你定稿。**


**界面上一共挂过两台引擎。2026-10-16 起只剩一台。**

| 引擎 | 出什么 | 等多久 |
|---|---|---|
| **YuE2**（本机苹果 MLX 版） | 一首**带人声的歌**，外加一份**能改的谱子**（ABC + MusicXML） | 快档约四分半，标准档约十分钟 |
| ~~**Composer Step**（ACE-Step 1.5）~~ | **2026-10-16 拆了**（省出 10 GB）—— 理由和装回来的办法见下面 | — |

> ★ **为什么拆**（用户 2026-10-16 定的）：它在本机**只能出一分钟以内的一段**
> （再长就会被内存保护按停），生成时又很吃内存；而他买了 ACE Studio，
> 那套活由 ACE Studio 接。**想装回来**：代码和运行环境都还留着（1.6 GB），
> 只差 9.4 GB 权重 —— 跑第五章那条 `fetch_models.py`（ModelScope，十几分钟）。
> 界面上那个下拉现在只剩 YuE2；旧记录写着 `acestep` 的会自动落到 YuE2。
>
> ★ **「让它唱」那个勾选框**（已拆的那台上的，2026-10-16 实测定的名）：它原来是
> 照上游文档抄的「让内置语言模型补全风格与歌词」，其实**它是"唱不唱"的总闸**：
> 同一首、同一段词、同样 3 分钟、同一个种子，关着只出音乐，打开就照词唱。
> 装回来之后，这个开关仍然有效、**默认仍然关着**。

（下面各章里凡是写「Composer Step 那台」的地方，都指已拆的那台 —— 留着是为了
装回来时有据可依。）

## 零、先把它跑起来（第一次接触的人看这一节）

### 这台机器上需要什么

| 要什么 | 说明 |
|---|---|
| macOS 14 或更新 | 系统框架（SwiftUI / AVFoundation）都是系统自带的 |
| Apple 芯片（M1 及以上） | 出歌那条走 Metal；只做「谱子出声」的话 Intel 也行，但你得自己试 |
| Command Line Tools | `xcode-select --install`。**不用装完整 Xcode** |

### 三步

```sh
git clone https://github.com/dajie2014/inspiration-assistant.git
cd inspiration-assistant
./gui/build.sh release        # 编译 + 打包，会装到「应用程序」
```

编译完在「应用程序」里找 **灵感助手**。第一次打开可能被 Gatekeeper 拦
（没签名），右键 → 打开 即可。

**不想装也能用一半**：不装任何模型，`谱子出声`（照谱奏）照样能用 ——
它只靠 macOS 自带音源。

### 三件「可选」的东西（都不在仓库里，自己装）

仓库**不带**任何模型权重（几个 GB）。三件各自独立，缺哪件就少一块功能：

| 想要的功能 | 自己要装什么 | 装好之后 |
|---|---|---|
| **出一首歌**（照谱唱） | YuE2 本地版（`mlx-Yue`）+ 它的权重 | 设 `ACE_LOCAL_ROOT` 指到本仓库根目录 |
| **音频 → 谱 / MIDI** | `audiocpp_cli` + SheetSage2 / MuScriptor 两个 GGUF | 在**偏好设置**里指一下程序位置，或设 `CS_AUDIOCPP_DIR` |
| **谱面能改 / 和弦核对** | 本仓库的 `sheetsage2-service/`（Python 3.11） | 见那个目录的 `README.md` |

### 环境变量速查

| 变量 | 干什么 |
|---|---|
| `ACE_LOCAL_ROOT` | 本仓库根目录（含 `render_adapter.sh` 的那一层） |
| `CS_AUDIOCPP_DIR` | `audiocpp_cli` 所在目录 |
| `CS_STUDIO_DIR` | 谱面工作室（可选）所在目录 |
| `CS_NODE` | node 可执行文件（谱面工作室用） |
| `CS_OUTPUT_DIR` | 强制输出目录（自检用，不写进偏好设置） |

### 许可（很重要，先看这一段）

本仓库是**壳**，真正干活的是别人的模型。各自的协议不一样：

- **ACE-Step 1.5**：Apache-2.0（但它的**权重**另有条款）
- **YuE2**：标注非商业 —— 用它做出来的东西**别拿去卖**
- **SheetSage2 / MuScriptor**：偏研究用途（见它们各自的模型页）
- **abc2xml / xml2abc**（Wim Vree）：GPL 系

⇒ **拿本仓库做商业产品之前，把自己要用的那几样逐条看完。**
本仓库自己的代码许可见 `LICENSE`。

## 一·五、和 Live / ACE 的联动（2026-10-18 加）

界面右边那一排按钮就是它：

| 按钮 | 送什么 | 落到哪 |
|---|---|---|
| **谱子 → ACE** | MusicXML（歌词与速度一起进去） | ACE 的唱轨 |
| **音频 → ACE** | 音频 | ACE 的音频轨 |
| **Live 选中 → ACE** | Live 里选中的 clip：音频按起止裁成 wav；MIDI 写成 `.mid` | ACE |
| **ACE 选中 → Live** | ACE 里选中的轨，渲染成 wav | Live 编曲视图的「来自 ACE」轨 |
| **连 Live** | — | 两边都开着就自动连；生成完自动落进「AI 草稿」轨 |

**速度两个方向都跟着走**：ACE 里音频尾部那个 BPM 会读回来（`clip beat-content`）；
往 Live 送时发送端先量一个 BPM——**空工程才写工程速度，工程里已经有东西就只回报**。

喂给 Live 的只有音频（切段、循环、分轨都在 Live 里做）；谱子只在往 ACE 送时用。

## 一·六、两个「转换」：音频 → 谱，谱 → 声音（2026-10-24 加）

这两个按钮是**对称**的，做的都是"搬家"，不是"创作"：

| 按钮 | 进 | 出 | 用哪套 |
|---|---|---|---|
| **上传音频** | 一段录音（wav / mp3 / m4a / flac 都行） | `草稿.abc`、`草稿.xml`、`拆轨.mid` | `audiocpp` 的 SheetSage2（出谱）与 MuScriptor（出 MIDI） |
| **谱子出声** | 一份 MusicXML | 一个 wav，当场播放 | **macOS 自带音源**，不靠任何模型 |

**「上传音频」会先问你要什么**：草稿谱 + MIDI / 只要谱 / 只要 MIDI。
两个都拆会跑两个模型（串行，各占几 G 内存），多等半分钟左右。

- 谱子是**草稿**：主旋律 + 和弦，不是总谱；混音越厚越糊。
- MIDI 是**从音频扒的**：节奏跟着实际演奏走，不一定卡网格，量化前先听一遍。
- 每条 MIDI 轨都带乐器名，按音色号写**标准英文名**。
  **故意不写中文** —— Dorico 里出现中文会打断视线，而且 MIDI 里的文本编码各家读法不一，
  中文容易乱码；英文（纯 ASCII）谁都读得对。界面上会用中文告诉你拆出了哪几轨。
- 一字多音**两个模型都给不了**，这一步还是 ACE Studio 的活。

**「谱子出声」是把谱面原样发成声音**：音高、时值、连音线（tie）、和弦、休止、
中途变速，全按谱面来。它**不加表现、不猜**，所以它回答的是
「我写的这张谱，听起来是我想的那样吗」。想要好音色，把同一份谱子拖进 DAW 或 ACE。

⚠️ 它和「生成」的区别（别混）：**「生成」是让模型照谱唱**，会加气口、加表现，
也可能跑偏；「谱子出声」是核对谱面，一个音都不改。

## 一·七、给声音换一副嗓子：挂 LoRA（2026-10-24 加）

「生成」之前可以挂一份社区调好的 LoRA（`.safetensors`）。它调的是**唱法、音色** ——
同一个人唱得偏气声、偏沙哑、偏某种风格，就是这一层在管。

- 入口在右栏：**挂 LoRA** → 选文件。挂上之后按钮上直接写文件名（免得忘了自己挂着什么），
  旁边的「不挂」一键摘掉。
- **它不改咬字。** 挂着它也不会让"字唱得准"变好 —— 那是模型本身的事，跟换嗓子是两码事。
- 不挂就一个参数都不传，行为与之前完全一样。
- 要求 mlx-Yue 是 **2026-10-13 版或更新**的（旧版不认 `--lora`）。

## 一·八、谱面工作室：改谱、重唱、看简谱、打 PDF（2026-10-25 加）

菜单「**工作室 → 进入谱面工作室…**」（⇧⌘Y）打开一个**本机网页**
（`127.0.0.1:8808`，零外部依赖、全程离线）。选中了哪一首，就把那首的谱带进去；
手上没谱就只开页面，可以从里面「导入 MusicXML」。

- **只能改音高**（半音 / 八度），时值和音符个数是锁住的 —— 模型是「一个字对一个音符」
  顺着填的，音符数一变，后面的字整体挪位。
- 谱面按**给人看的高度**显示（人声与伴奏都低八度，跟导出的 MusicXML 一致）；
  点「重新唱」时服务端自动升回模型高度，交回主程序开一轮新的生成
  （进度条、历史、送 ACE/Live 都在那边）。
- 顶栏可切**五线谱 / 简谱**（1 一律是主音，不分大小调）；**导出 PDF** 走浏览器打印。
- 谱面纸上方的**歌名点一下就能改**；右边能填「**作词**」「**作曲**」，打印时会跟着出去。
- 右栏「**最近的作品**」：列出**你自己的输出文件夹**里带谱子的旧作品，
  点一下就把那首载进来（风格、词、种子一起带过来），不用每次先回主程序送一遍。
  刚生成完新的一首，点名单右上角「刷新」。
- 底下有**播放条**：**蓝色键放谱子**（电脑照着谱现合，改了音高立刻能听），
  **橙色键放这一首的模型音频**（当初真唱的那份）。两个都能暂停、拖进度；**没有录音**。
- 「谱子原文」里可以**复制 ABC**。
- 细节与坑见 `../yue2-studio/README.md`。

## 一、它由哪几块组成

```
My Songwriter.app        ← 界面：填参数、看进度、试听、导出（不含任何推理逻辑）
        ↓ 按「引擎」选一条路（两条同契约：params.json 进、progress.json 出）
        ├── render_adapter.sh   ← ACE-Step 那条：夹紧时长、看门狗、收尾释放内存
        │        ↓ 调用
        │   scripts/headless_generate.py  ← 无头推理：加载模型 → 生成 → 存 wav → 退出
        │        ↓ 调用
        │   backend/ACE-Step-1.5/         ← 上游官方代码 + 内嵌 Python + 权重（10 GB）
        │
        └── yue2_adapter.sh      ← YuE2 那条：翻译参数、报进度、收尾把音频与谱子摆好
                 ↓ 调用
            ../yue2-local/yue2   ← YuE2 本体（独立项目，MLX 权重约 10 GB）
                 ↓ 收尾时调用
            ../yue2-local/abcxml ← 顺手出一份 Dorico 能直接打开的 MusicXML
```

`scripts/export_audio.sh` 负责把成品导成 MP3 / WAV —— **两台引擎的产物都吃**
（ACE-Step 出 wav、YuE2 出 flac，转换都走 ffmpeg）。

**YuE2 装在哪儿**：默认按兄弟目录 `../yue2-local` 找，可以用环境变量 `YUE2_ROOT` 改。
找不到时界面当场报出来（退出码 7），不会让你等半天才发现。

## 二、怎么用

双击项目根目录里的 **My Songwriter.app**。

**开头会先来一片星空**（`WelcomeView.swift`）：程序化画的星云 + 二百多颗会闪的星，
中间浮着那支跟图标同字形的白谱号（Apple Symbols 的 U+1D11E），
标语是「纯线下AI音乐创作」，标题那行字外挂着一层很淡的星尘。
约 2.6 秒自动淡出，**点一下 / Esc 立刻进** —— 用户要它好看，但**不许挡路**。
自检：`CS_WELCOME_ONLY=1`（只开它）、`CS_WELCOME_LINGER=1`（不自动消，供抓图）、
`CS_NO_WELCOME=1`（别开它）；跑任何别的 `CS_*` 自检时它一律不出现。

- 左边是条目列表，**每次生成一条**；关掉重开还会在（会自动扫描输出目录）
- 右边最上面先选**引擎**：`Composer Step`（一段音乐，快）或 `YuE2`（带人声的歌 + 谱子，慢）
- 右边填：歌词、风格、BPM、调号、时长、模式、质量（步数）、语言
  —— **选 YuE2 时只剩「档位」一栏**（快·8 步 / 标准·32 步），其余那几格它用不上
- 底部蓝色大按钮「生成」；生成中可以点它变成的「停止」
- 生成完，播放条右边出现「导出」（MP3 320k / WAV 原样）和「显示文件」；
  YuE2 那一首还会多一个**「谱子」**按钮（在访达里定位那份 MusicXML）
- 底部「生成」按钮右边是「打开文件夹」——打开存放全部结果的文件夹

**菜单栏「文件」里还有四条**（2026-10-12 加，用户提的：
「把它生成的音乐保存在一个地方，让我事后进打谱软件继续打磨」）：

| 菜单项 | 干什么 |
|---|---|
| **新建一首**（⌘N） | 等同左上角那个按钮：清空表单写新的 |
| **载入一首…**（⌘O） | 从写过的曲子里挑一首，把参数填回右边 |
| **导出谱子（XML / abc）**（⌘S） | 点一下就存进 **`~/Documents/My Songwriter 谱子/`**；**按住 Option 点**则弹保存面板自己挑位置。重名**不覆盖**，加 `-2` |
| **导入谱子…**（⇧⌘I） | 选一份外来 XML/abc：**只转格式**，或者**照它重唱一首**（用选中那一首的词与风格） |

> 「照它重唱」就是用户那条工作流的闭合处：YuE2 出谱 → 进 Dorico 改 →
> 导回来重唱。给了谱子它就不用自己写谱，实测快得多（65 秒那首重唱只花 35 秒）。
> 带谱子生成时，界面表单里会有一行蓝字写明（免得跟平常那次搞混）。

**界面最底下还有两个转格式按钮**（同一天加的，用户说「纯粹转格式，两个格式之间的互转」）：
**「XML → ABC」** 与 **「ABC → XML」**。点一下挑个谱子文件，就在**原文件旁边**
生成另一种格式（`abcxml` 的规矩：同目录同名、只换后缀）。
**只管格式** —— 不生成、不看当前选中哪一首。⚠️ 覆盖式：目标已在时会先问一句
（防的是他 Dorico 改过的那一份被默默抹掉）。自检：`CS_CONVERT_SCORE=<文件>`
（`CS_CONVERT_YES=1` 跳过那一问）。

> ⚠️ 这两个入口原先一个是**光秃秃的图标**、一个是**一行小字**，用户 2026-10-11
> 说找不到，所以都改成了写字的按钮（「显示文件」还加了图标和边框）。

### 生成的东西叫什么名字

结果落在 `output/<时间戳> <名字>/`。**ACE-Step 出 `<名字>.wav`；YuE2 出 `<名字>.flac`，
外加同名的 `<名字>.abc`（谱子）和 `<名字>.xml`（给 Dorico 直接打开的 MusicXML）**；
当次的 `params.json` 两边都有。

⚠️ **谱子上只有旋律和和弦，没有歌词**（2026-10-12 核过：`.abc` 里没有 `w:` 行，
转出来的 `.xml` 里 `<lyric>` 数是 **0**）。进 Dorico 改的是**曲** ——
词还在界面里，也在同一个文件夹的 `params.json` 里。

`<名字>` 取「歌词第一行**真正的词** → 风格描述」，最多 40 字。2026-10-11 之前这里是一串
uuid（上游给产物起的名，形如 `5c81fffe-d44e-….wav`），在访达里根本认不出
哪首是哪首 —— 所以改成现在这样。

⚠️ **`[Verse]`、`[Chorus]` 这类结构标记不算词，会被跳过**。2026-10-12 加 YuE2 时撞见的：
它那边的歌词模板里标记行更多，不跳的话一整列作品会全叫「[Verse]」，
隔天在访达里根本分不出谁是谁。

**时间戳为什么放在名字前面**：访达里按名字排序就等于按时间排序，最新的一直在最上面。

⚠️ 这条规则有**两份实现**，因为它们各管一头：**目录由界面创建、wav 由脚本命名**。
- 界面：`gui/Sources/LocalMusic/FileName.swift`
- 脚本：`scripts/headless_generate.py` 的 `safe_file_stem`

**改一边就要改另一边**，改完跑这个自检 —— 它把同一批用例同时喂给两边、逐条比对：

```sh
./gui/check-naming.sh
```

三种模式：

| 模式 | 用途 |
|---|---|
| 生成 | 整首新写，词曲都按你填的来 |
| 重绘 | 只重画其中一段（要选源音频 + 起止时间） |
| 参考音频 | 按参考音频的织体与音色来写 |

> 底注：**Repaint 会重写旋律；想丰富织体，优先用「参考音频 + 生成」这一路。**

## 三、这台机器上的实测数据（Apple M1 Max / 64 GB）

| 事情 | 实测 |
|---|---|
| 15 秒音频、8 步（低档） | 全程约 **32 秒**，其中扩散 **2 秒** |
| **5 分钟音频、8 步** | 全程 **93 秒**，其中加载 26 + 扩散 26 + 渲染波形 39（产物 57 MB） |
| 模型加载 | 每次生成都要重新加载，约 **26 秒**（这是固定开销） |
| 权重体积 | 10.09 GB（turbo DiT + 1.7B 语言模型 + 文本编码器 + VAE） |
| 后端计算 | MLX（Apple 原生加速），`MLX DiT diffusion` |
| **推理进程峰值内存** | **14.84 GB**（实测三次完全相同：60 秒与 300 秒都一样） |

**注意一个反直觉的点**：曲子越长，**「把音频渲染成波形」那一步越可能比生成本身还慢**。
5 分钟那次，扩散花了 26 秒，而 VAE 解码花了 39 秒（为了省内存走了分块解码）。

### ⚠️ 生成期间内存会吃紧（实测曲线）

内存**跟曲子长度基本无关**（60 秒和 5 分钟都是 14.84 GB 峰值），但生成**当下的整机压力**很大：

```
生成前    系统空闲 34 GB
生成中    空闲 15 → 12 → 10 → 0 GB      ← 掉到几乎没有了
生成后    空闲 48 GB                     ← 立刻全部还回去
```

原因是除了进程那 15 GB，**MLX 会把统一内存锁住**（`wired` 一度涨到 17 GB，这部分不可回收）。

**所以实操上**：生成前把 ACE Studio 之类的大工程存一下，别同时跑重活。
跑完会全部还回来，不用管。

**★ 2026-10-12 起，跑起来之后还有一道刹车**（`Tools/memory_guard.py`）：
它每两秒量一次 —— 生成进程占了多少、整机还剩多少、**有没有开始拿硬盘当内存**、
系统内存压力正不正常。**任何一条越线，它当场把这一趟按停**，界面上写清楚是哪条踩的：
宁可这一趟白跑，也不让机器被拖垮。

正常生成碰不到它：实测进程树峰值 13.5 GB（线画在 20 GB）、
整机可用最低 22.7 GB（线画在 2 GB）、全程一次 swap 都没动。

时长上限 **300 秒**（最初规格要求，脚本里硬夹紧）：填 400 秒会被自动压到 300，不会拒绝。
上游模型本身支持到 **10 分钟（600 秒）**，想放开改 `render_adapter.sh` 顶部的
`MAX_AUDIO_SECONDS` 即可。按上表线性推算，10 分钟大约 2.5 分钟出结果 —— 但**未实测**。

**中断也会收干净**：界面被强退、终端按 Ctrl-C 时，脚本会杀掉推理进程并把状态写成
「已中断」，不会留孤儿进程、也不会让界面卡在「进行中」。界面启动时还会清掉上次残留的
「进行中」状态（防 `kill -9` 那种接不住的）。这两条都实测过。

### 试听走哪块声卡（偏好设置）

主界面右下角的**齿轮图标**，或者按 **⌘,**。里面把系统里所有能出声的设备都列出来，
点一下就选中（比如你的 Focusrite / Scarlett）。选中的那行会亮起来。

- 选的是**设备名字**，不是编号 —— 编号每次开机都会重新分配，存编号的话重启就指错了
- 设备拔掉或改名了，会自动回落到「跟随系统」，并在界面上如实告诉你

技术上：macOS 自带的简易播放器只会往系统默认设备送声音，所以试听换成了
`AVAudioEngine`，在开播前把它的输出单元指到选中的那块设备上（`AudioDevices.swift`）。

## 四、给程序调用的接口

界面和 Composer Assistant 走的是**同一条命令、同一个进度文件**。

### 4.1 生成

```sh
./render_adapter.sh --params <参数.json> --out-dir <输出目录> --progress <progress.json>
```

**换 YuE2 那台引擎，就是把脚本名换掉，其余一个字不动**（同一个契约）：

```sh
./yue2_adapter.sh   --params <参数.json> --out-dir <输出目录> --progress <progress.json>
```

参数里多一个 `"engine"` 字段（`"acestep"` 或 `"yue2"`，2026-10-12 加）——
界面按它选脚本；**老任务没这个字段，一律当 `acestep`**。
两台都用 `steps` 表示质量档：ACE-Step 是扩散步数，YuE2 是声学合成的步数（8 快 / 32 标准）。

`yue2_adapter.sh` 多做的两件事：把 YuE2 每一行进度翻译成百分比（它的进度是
「写谱 → 想怎么唱 → 奏成声音 → 解码」四段，不是线性的），收尾时**顺手出一份
MusicXML**（调 `../yue2-local/abcxml`，失败不算整趟失败）。

参数 JSON：

```json
{
  "prompt": "风格描述",
  "lyrics": "歌词，或 [Instrumental]",
  "title": "这一首叫什么",
  "mode": "generate | repaint | reference",
  "duration": 60,
  "bpm": 120,
  "keyscale": "C Major",
  "steps": 8,
  "seed": 42,
  "thinking": false,
  "language": "unknown",
  "ref_audio": "",
  "src_audio": "",
  "repaint_start": 0,
  "repaint_end": -1,
  "cover_strength": 0.5,
  "abc_path": "",
  "plan_only": false
}
```

`title`（可省，2026-10-11 加）= **产物的文件名**。界面按「歌词首行 → 风格描述」
算好写进来；不传就退回用 `prompt` 起名；两个都没有则叫「未命名」。里面有斜杠
之类的非法字符会被换成下划线（规则见上面「生成的东西叫什么名字」一节）。

`abc_path`（可省，2026-10-12 加）= 「照这份谱子唱」：给一份 ABC 或 MusicXML 的绝对路径，
YuE2 就不自己现想谱子（XML 会先用 `abcxml` 转成 ABC）。ACE-Step 那条路不看这个字段。

`plan_only`（可省，2026-10-12 加）= **只要谱子、不唱**（界面上的「先出谱子」）。
YuE2 那条路会改跑 `plan` 子命令（约 40 秒），产物只有 `.abc` / `.xml`，没有音频；
进度里 `output` 为 `null`、`score` 指向那份 `.abc`。
★ 这一档**故意忽略 `abc_path`** —— 它要的就是"重新写一份谱"。
⚠️ 只在 `engine = "yue2"` 时有意义；给 ACE-Step 传它会被无视。

`thinking: false`（默认）= 不让内置语言模型替用户编歌词和音乐构思，完全照手填的内容走。

`seed`（默认 **42**，2026-10-20 起）= 随机种子。照谱唱实验里 42 这一版从第一个字
就接住了；`-1` = 每回随机，容易「进错门」（前面的词整段错位）。
同 seed 输出逐字节相同 ⇒ 默认值固定下来，结果才**可复现**。

退出码：`0` 成功 / `2` 参数错 / `3` 模型加载失败 / `5` 生成失败 / `7` 缺环境。

### 4.2 进度（progress.json）

```json
{"percent": 42, "state": "running", "message": "…", "detail": "…",
 "updated": 1791682137, "output": "/绝对路径/xxx.wav", "score": null}
```

`state` 四态：`idle` / `running` / `done` / `failed`。完成时 `output` 是音频的绝对路径。

**两个文字字段分工**（`detail` 是 2026-10-13 加的）：
`message` 回答"**现在在干什么**"（界面用大字显示），
`detail` 回答"**还要等多久 / 为什么慢**"（界面用小字接在后面）。
慢的那几步**必须**配一句人话 —— 光说"正在加载"，等的人只会以为卡死了。
两套适配脚本都得写这两个字段：`render_adapter.sh` 的 `write_progress` 第 4 个参数、
`yue2_adapter.sh` 的第 6 个参数（**排在最后**，插中间会让现有调用把音频路径当成一句话）。
⚠️ 界面另外还自己算一句「已经等了 X 分 X 秒」—— **它不读文件，是拿本机时钟算的**，
所以进度文件半分钟不更新时，那行数字照样在涨（这正是"没卡死"的证据）。

`score`（2026-10-12 加）= 这一趟出的谱子（那份 `.abc` 的绝对路径），没有就是 `null`。
**「只出谱子」那一档 `output` 是 `null`、`score` 有值** —— 别拿 `output` 冒充音频路径：
读的一方会据此把一条没有声音的记录当成"能播的歌"。出整首歌时两个都有。
文件是**原子写入**（先写 .tmp 再改名），读的一方永远读不到半截。

⚠️ **界面必须真的会刷新**：`BackendClient` 只是 `AppViewModel` 的一个普通属性，
它的 `@Published` **不会自动穿透**到界面订阅的那个对象上 —— 少了
`client.objectWillChange` 那一层转发，**生成期间界面一帧都不重画**
（2026-10-13 实测踩到：进度文件写到 20%，界面还停在 0%）。改这一块时
**判据是"抓图上的百分比 == 文件里的百分比"**，不是"看起来在动"。

### 4.3 导出

```sh
./scripts/export_audio.sh --input <源.wav> --output <目标.mp3|目标.wav> [--format mp3|wav]
```

MP3 走 `libmp3lame` 320 kbps；WAV 若是从 wav 导出则直接拷贝，不重复转码。

### 4.4 自检（让界面自己按下「生成」）

```sh
CS_AUTORUN=1 "./My Songwriter.app/Contents/MacOS/LocalMusic"
```

带上这个环境变量启动，界面会**自己**用当前表单的参数跑一次生成。
用途是让「界面 → 壳脚本 → 后端」这条最长的链路可以**被自动验证**，
不必靠人去点鼠标（2026-10-11 就是靠它验完的）。

YuE2 那两条路各有开关（2026-10-12 加）：

```sh
CS_SCORE_ONLY=1      "./My Songwriter.app/Contents/MacOS/LocalMusic"   # 只出谱子（约 1 分钟）
CS_SCORE_THEN_SING=1 "./My Songwriter.app/Contents/MacOS/LocalMusic"   # 先出谱，出完自动照它唱
CS_SCORE_ONLY=1 CS_DEMO=1 "./My Songwriter.app/Contents/MacOS/LocalMusic"  # 同上，但填一段像样的词（给手册拍图用）
```

后者最接近「先出乐谱、再出歌」的实际用法：先按「先出谱子」，回调拿到谱子后
自动接着按「生成」。它比平常那次慢一倍（两段都要等），但验的是**完整的那条来回**。

「送进 ACE Studio」也有开关（2026-10-13 加）：

```sh
CS_SEND_TO_ACE=1 "./My Songwriter.app/Contents/MacOS/LocalMusic"                        # 送列表里第一条有产物的
CS_SEND_TO_ACE=1 CS_SEND_TITLE="示例歌名" "./My Songwriter.app/Contents/MacOS/LocalMusic"  # 点名送哪一首
CS_SEND_TO_ACE=1 CS_SEND_WHAT=score "./My Songwriter.app/Contents/MacOS/LocalMusic"     # 只送谱子（audio 则只送音频）
```

界面上一共是**两个按钮**（「谱子 → ACE」「音频 → ACE」），`CS_SEND_WHAT` 就是给它们
各留一条自检路；不写这个变量＝两样**依次**送（共用一份状态，不能叠着来）。

它跨进程去调 ACE 自带的 `acestudio-cli`，终端会打两行
`[CS] ACE 传输 —— …` / `[CS] ACE 传输结果 —— …`。
**验的时候要回 ACE 那边看**（判据不在这个程序里）：

```sh
CLI="/Applications/ACE Studio.app/Contents/Helpers/acestudio-cli"
"$CLI" track list --json                       # 应该只有一条 Sing + 一条 Audio
"$CLI" clip lyrics --track-index 0 --clip-index 0 --json   # 歌词句数与第一句
"$CLI" tempo get --json                        # 速度应与谱面一致
```

`CS_SEND_TITLE=<子串>` 有必要存在：**哪一条有歌词是因作品而异的**
（实测「照谱唱」那一版的产物 XML 里没有 `<lyric>`，送过去 ACE 只能唱「啦」），
所以验歌词时要能点名。

平时正常双击启动完全不受影响 —— 没有这些变量它什么都不做。

验证一次自检是否成功，看三样：

```sh
cat output/progress.json                    # 应该是 {"percent":100,"state":"done",...}
ls output/$(date +%Y%m%d)*/                 # 应该有一个新的 wav（只出谱子那档则是 .abc + .xml）
cat "$(ls -t logs/gui-*.log | head -1)"     # 应该以「退出码 0」结尾
```

## 六、已知限制与坑（都踩过，写下来免得再踩）

1. **`BF16` 开关在 Mac 上不起作用。** v1.5 的 MLX 后端不接收精度参数，精度由上游自己定。
   这个开关保留着，只为将来换到 NVIDIA 机器（PyTorch 路径）时才有意义。
2. **每次生成都要重新加载模型（约 40 秒）。** 这是「跑完就释放内存」的代价 ——
   规格要求如此。想要更快就得做常驻模式，那是另一个取舍。
3. **首次生成前要等模型加载**，界面上的说明卡会说"正在启动作曲的 AI…"，
   旁边「已经等了 X 分 X 秒」一直在涨 —— 那就是它还在干活的证据。
   ⚠️ 这一条原先写的是"进度条停在 0%"：**那是 2026-10-13 修掉的一个真 bug**
   （界面持有 `BackendClient` 却没有转发它的变化 ⇒ 生成期间一帧都不重画），
   不是"在加载模型"的正常现象。
4. `~/.cache` 一类目录在受限环境下写不进去，所以脚本把 HF / matplotlib / torch 的缓存
   全部重定向到项目内的 `_cache/`。
5. **macOS 自带 bash 是 3.2**：变量名后面紧贴中文字符会被解析错，必须写 `${VAR}`。
6. **Swift 的 Codable 合成解码遇到缺字段会整体失败**，属性上写默认值救不了；
   要容错就得手写 `init(from:)`（且必须写在 extension 里，否则会把成员构造器挤掉）。
